# 模型兼容与总管行为

兼容层参考 Undefined 的请求转换、工具生命周期和原生推理回放设计，独立于其机器人上下文。三种 API 通过相同的 Provider 流事件和操作服务驱动总管。

本文的模型配置用于 Chiliarch AI 总管。托管 Codex／Claude／OpenCode 直接沿用本机原生模型、服务商、认证和其他设置，平台不把此处的模型或 API Key 下发给它们；原生订阅与 API 来源按各工具自身优先级选择，用量统计不等于实际收费凭证。见 [runner 与原生配置](configuration.md#本机-runner-与原生配置)。

总管接收的每个业务工具定义直接说明用途、输入参数、关键状态、后续处理和审批边界；三种模型 API 使用同一套工具定义，不要求模型先读接入文档。下级 agent 的 MCP 工具另有同样自包含的说明，并明确主动读信要求，见 [运行中工具与通信指引](agents/tools.md)。总管由持久事件触发处理来信，不能照搬下级主动轮询收件箱的工作方式。

## 配置模型

| 字段 | 用途 |
|---|---|
| api_mode | chat_completions / responses / anthropic |
| model | 服务商模型名称，空值表示未配置 |
| base_url | 覆盖 SDK 默认地址；填写对应 API 根地址，不填写某次请求的最终 endpoint |
| api_key | 认证 Key，可用环境变量覆盖；自建无认证网关可留空 |
| headers | 自定义请求头，支持网关认证或版本标记 |
| request_params | 模型特有请求参数；不能替换平台 transcript、tools、model、stream 等控制字段 |
| timeout / retries | SDK 请求超时与有限重试 |
| context_window | 模型上下文窗口，默认 200000 tokens，达到 90% 自动压缩 |
| temperature | 可省略，不接受的模型保持空值 |
| reasoning_enabled / reasoning_effort | 请求模型推理及强度；按 API 映射 |
| thinking_enabled / thinking_budget_tokens | thinking 参数与预算；服务商不支持时关闭 |
| reasoning_replay | 下一轮保留服务商兼容的原生推理载体 |
| include_usage | 请求流式 usage，网关不支持时关闭 |
| system_prompt_as_user | Chat 模式中将系统提示词以 user 角色发送，兼容不接受 system 的网关 |
| tool_choice | 可选的服务商工具选择参数 |

不要把业务消息、工具 Schema 或流式控制字段塞进 request_params；它们由平台生成。保留字段冲突会报错，而非静默覆盖。兼容开关按网关能力配置，不按某几个模型名硬编码。

默认不发送 `max_tokens`、`max_completion_tokens` 或 `max_output_tokens`，由服务端决定输出长度。明确需要覆盖时，可以在 `request_params` 中写对应 API 的参数；平台不会额外加入另一个输出上限。

原生 [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create) 要求 `max_tokens`，没有可依赖的服务端默认值。选择该 API 时，在“额外请求参数（JSON）”填写它，例如 `{"max_tokens":32768}`，值需符合实际模型能力。提供默认值的兼容网关可保持空对象；请求仍被网关拒绝时按其文档设置参数。

## 三种 API

**Chat Completions** 使用 OpenAI SDK，流式收集文本、公开 reasoning 字段、分片 tool_calls 和 usage。函数参数直到完整 turn 结束且 JSON Schema 校验通过后才执行。reasoning 原字段可用于下一轮兼容回放。

**Responses** 使用 Responses 事件；保持 message、function_call、function_call_output 与 reasoning items 的原始顺序。采用本地活跃窗口的 stateless replay：压缩前完整回放，压缩后回放接续摘要与保留片段；不用 previous_response_id 把本地生命周期与远端持久状态绑死。加密 reasoning 作为回放元数据保留，不作为可读思考显示。

**Anthropic Messages** 转换为 text、tool_use 和 tool_result blocks，保留 thinking/redacted_thinking 与签名结构。工具结果与调用匹配，不能把显示文本重新拼成服务商签名块。

可读思考内容或摘要与原生签名/密文分开保存。WebUI 只显示服务商明确公开返回的内容；没有 reasoning 的模型不会生成装饰性“思维链”。关闭 reasoning_replay 过滤推理载体，但保留合法工具调用结构。

## 上下文窗口与自动压缩

`model.context_window` 默认 **200000**。每次模型请求前，以及回答结束时检查当前窗口；使用量达到 **90%**（默认 180000 tokens）自动 compact，之后继续当前工具循环或保存给下一次问答使用。工具轮次、消息条数和全局并行运行不再设置固定上限；同一会话的运行互斥、审批与运行超时仍然有效。

上下文包括系统提示、工具定义、消息、工具调用与结果及兼容回放。服务商 usage 优先：当前轮次的输入加输出代表当前窗口，并非把历史所有请求的计费用量累加；之后新增的工具结果、用户消息以估算增量补入。Anthropic 缓存创建与缓存读取同样占用输入窗口；OpenAI 的 cached_tokens 是输入的一部分，不重复相加。未返回 usage 时按实际待发送结构的 UTF-8 字节数约算 tokens，方法参考 Codex 的本地估算；不同模型分词器存在差异，界面会标注“约”，因此配置值应匹配真实模型窗口。系统提示、工具定义或模型配置变化后，旧测量基线失效，重新估算。

压缩使用**当前配置的同一模型**做额外的摘要请求，不依赖服务商私有 compact endpoint，因此三种 API 和兼容网关共用一套逻辑。摘要保留目标、用户修正、限制、agents/任务/请求/操作 ID、已确认结果、待办和未知状态。当前用户问题保留原文，最近的调用及全部匹配结果按完整组保留；过大的旧结果整体进入摘要资料，不截断出孤立的工具结果。超过窗口的既有历史或单条巨大结果会拆分为有序片段，分批生成接续摘要，不直接丢弃前面的资料。

摘要请求不提供业务工具，不执行返回的工具调用，也不把摘要文本当成许可。等待审批的调用先完成允许或拒绝及结果收集，再检查压缩；原生签名、密文和推理回放不拼进可读摘要。压缩期间 UI 显示“正在压缩上下文”，摘要本身不作为总管答案插入时间线。

完整消息、可见思考、工具时间线及原生回放仍在数据库中保留；运行单独保存活跃模型窗口和 token 基线。压缩成功后原子保存摘要窗口，后续问答与服务重启沿用它。服务在活跃执行中重启仍会中断该运行，不自动重复外部副作用；等待审批的运行按原规则恢复。空摘要、工具调用、模型错误、无有效缩减或取消不会提交半成品，原上下文保留并停止当前运行，页面给出错误或取消状态，避免盲目重复已执行的操作。若系统提示/工具定义或必须保留的当前问题本身已占满窗口，需调整窗口或缩短输入，不能靠摘要隐藏这部分内容。

压缩会产生额外模型请求、token 费用和等待时间；多次摘要可能损失细节，可通过完整聊天记录核对。设计参考 [Codex 的本地压缩实现](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs) 与 [OpenAI 上下文压缩说明](https://developers.openai.com/api/docs/guides/compaction)，这里采用可跨 API 使用的文字摘要。

## 对话页面与键盘

页头常驻“新会话”按钮，会话列表位于右侧，默认收起。桌面鼠标移到工作区右边缘时自动显示，离开后收起；点击页头按钮可以固定展开，Escape 或关闭按钮可以收起。鼠标悬停展开不会抢走输入焦点；触屏和键盘使用按钮打开，小屏幕使用模态抽屉。

列表中的每条会话都提供重命名和删除按钮。重命名可直接编辑标题，删除需要确认；正在运行或等待审批的会话需先停止再删除。删除当前会话后回到新对话界面，其他会话保留。

用户会话首次成功完成问答后，后台使用当前配置的模型生成简短标题，完成后通过持久事件更新列表和页头。命名会额外调用当前模型，只发送这次问题和最终可见答案，不发送工具结果、公开思考或原生回放，也不提供业务工具。用户已命名的会话不会被覆盖；命名失败保留原标题，服务中断后不自动重复命名，不影响已完成的回答。下级 agent 的关联会话保留原有标题。

消息在居中阅读列中显示，用户消息靠右，Chiliarch AI 的正文、公开思考与工具调用保留各自的显示区域。新增消息的保存时间沿同一会话的持久历史递增，同一时钟刻度或系统时间回拨不会交换用户消息与回答，也不会丢失下一轮的上下文。思考和工具详情可以折叠，便于连续阅读回复。

同一次回复按持久事件的 `seq` 顺序交错展示正文、公开思考和工具调用。例如“先检查机器”→查询工具→“发现任务未完成”→派发工具→最终回复会保留这一顺序，不将所有工具移到答案末尾。相邻的同类文本增量合并为一段；被正文或工具隔开的思考分别折叠。工具结果和审批状态更新原工具位置，刷新也从已保存事件重建同一时间线。不同运行与不同工具轮次的调用分别识别，重复续传不会重复显示或拼接正文。

底部圆角输入区随内容增高，较长输入在框内滚动。发送快捷键如下：

| 按键 | 行为 |
|---|---|
| Enter | 发送消息 |
| Shift + Enter | 在输入框内换行 |
| Ctrl / ⌘ + Enter | 发送消息，保留组合键用法 |

输入法正在组合文字或确认候选词时，Enter 不提交消息。发送中显示受理状态；模型运行时可使用停止按钮。切换会话不会将旧连接迟到的输出拼入当前会话。

在当前对话页面内切换会话时保留各自未发送的草稿，刷新或离开页面后不保留。发送请求正在受理时暂时禁用会话切换，输入框仍可继续起草；原请求受理完成不会清空后来编辑的内容。完整回复和代码块均提供复制按钮及成功、失败反馈。

阅读历史时，新输出不会强制把页面拉回底部。离开底部后显示“回到最新”按钮；点击它或发送消息会重新跟随最新输出。消息进入、会话抽屉和折叠详情使用短动画，并遵循系统的“减少动态效果”偏好。

## 流式、取消与错误

真正的增量事件在模型 turn 完成前已保存并发送。浏览器通过 SSE 接收 text_delta、reasoning_delta、tool_start、tool_end、usage、approval_required 和运行终态。会话快照同时包含聚合消息与事件时间线；浏览器只用事件还原各段顺序，不再次累加快照正文。事件有递增 seq，刷新从同一会话快照的 last_event_seq 续传，避免丢帧或重复拼接。

工具行展示名称、脱敏参数、结果、许可状态和执行状态，需要许可时在对应工具行下方直接允许或拒绝；折叠参数与结果仍保留审批入口。等待审批的状态和对应工具事件在同一事务保存，服务在通知页面时停止仍保留许可。审批按持久 approval_id 绑定具体调用，不按工具名匹配，也不会因刷新或切换会话而移到其他调用。批准/拒绝进入统一服务，批准绑定原参数；总管恢复后取已完成工具结果，不再执行一次。

对话页面不常驻显示下级请求、最近任务或全局审批栏。Chiliarch AI 通过工具处理这些业务；需要手动查看时进入 Agents 管理的对应 agent 详情。

关闭浏览器不停止模型 run。取消会撤回尚未执行的审批；已产生外部副作用的工具不能靠取消“撤销”，应检查操作结果。SDK 只允许有限请求重试；已经产生增量事件的中途流失败不会自动重放整个 turn。

进程中断后，正在运行的模型操作标为 interrupted，等待审批的执行可恢复。恢复保留已存的非秘密模型设置，并使用当前密钥/请求头；嵌套敏感请求参数也从当前配置恢复。若 API 模式、模型或 endpoint 已变，要求用户检查状态再重试，不能把旧调用续到不兼容模型。

## 下级来信

agent.contact 和需要总管决策的 agent.request 持久进入下级 inbox；同伴发现、讨论查询及模式允许的确定性通信/产物操作直接由统一服务处理，不逐条调用模型。携带 `metadata.task_id` 的消息只有在任务确实属于发送 agent 时，才回到该任务的目标会话；无法确认关联时建立独立来信会话，不能冒用另一个 agent 的任务关联。托管 MCP 请求自动携带任务身份。需要总管但未配置模型时保持 pending；配置后继续处理。同一消息重传不会重复创建来信。请求内容作为下级消息而非系统指令送入总管，响应和具体操作均经过服务端身份、Schema 和模式检查。

任务完成、失败、中断、取消或到期另进入持久协调队列，自动推动总管核对验收、安排下一步并汇总。目标关联的来信与事件共用原会话，已有运行或待审批时继续排队，不插入正在执行的模型轮次；常规进度和心跳不触发模型调用。同一会话当前积压的协调事件合并为一轮处理，每个目标的当前快照只提供一次，避免多个 agent 同时结束时逐条调用模型。整批事件与模型运行在同一事务绑定，审批和最终状态作用于整批；处理期间新到事件留给下一批。协调事件在聊天中显示简短说明，完整结构化资料保留在模型上下文中。

用户停止总管、遇到不可恢复的模型错误或耗尽自动恢复预算后，该会话暂停自动协调。后续协调事件和下级来信继续持久排队，不会立即启动另一轮绕过停止。用户发送新消息，或在“目标”页明确点击“继续协调”后恢复；普通修改标题或目标说明不表示恢复。停止前已经排队的“继续协调”同样不能越过后来发生的停止。暂停总管不会撤销 agent 已产生的外部副作用，也不等于停止远端任务，需查看任务状态并明确取消。

对于模型连接/传输故障、HTTP 408/429/5xx，总管会持久保存一条延后核查事件，默认按 5、10、20 秒退避，最多 3 次。原轮次仍显示失败，恢复时创建全新的核查轮次，读取现有历史和最新任务快照，先检查已有结果再决定下一步；不从失败前的工具列表重放执行。SDK 请求层 `model.retries` 与此分开。部分流发生网络异常时，未完成的工具调用不会执行；已完成的操作结果保留给核查使用。缺少完整结束标记、参数无效、401/403 认证错误和逻辑错误不会自动恢复。

重试次数、下次核查时间与原失败轮次一起入库，重启不会从零再试。超限后继续等待用户处理。用户在退避期间发送新消息会取代旧计划；调用 `cancel_chat_run` 可撤销该失败轮次的待恢复事件，若核查刚被领取则停止对应新轮次。配置字段见 [supervisor / model](configuration.md#supervisor--model)。

持续监护覆盖已入队、送达、接受、运行及正在请求取消的任务。默认 300 秒无任务更新、或 agent 超过离线阈值时，平台生成核查事件并唤醒原会话；若会话已有运行或处于暂停状态，则继续持久排队。同一次进度停滞/失联只提醒一次，进度上报和重连后重新计时。阻塞在前置依赖的任务和终态任务不产生此类提醒。监护不会主动连 agent，也不会因为失联就认定停止、改成失败或重派外部工作。

目标相关运行在服务重启后仍记录为 interrupted，另创建一次核对待办，提供当前目标、任务和已知操作结果。只恢复会话最新的中断；后来的用户停止、失败或已完成运行会阻止旧中断再次唤醒。总管据此决定等待、检查或明确重试，不重放旧工具调用；中断的核对本身可再次恢复，整批事件以及恢复期间新加入的任务关联保持完整，已处理的同一中断不会反复唤醒。等待审批仍按原有审批 ID 继续。目标未完成或取消前不能删除它的关联会话。完整工具和限制见 [目标与验收](coordination.md)。

agent 接入支持 [Codex App/CLI、Claude Code、OpenCode v2 与 v1 legacy](agents/index.md)，尚不包含 Undefined 厂商适配、模型池、RAG、多模态或文本工具封包恢复。不同网关的扩展不可能只凭名称保证兼容；请使用对应模式和实际行为测试验收。
