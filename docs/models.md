# 总管模型与对话

Chiliarch AI 是平台的总管。它查看 agents、安排任务、处理来信和验收结果。你可以在“总管对话”向它提出要求，也可以直接使用管理页面操作。

这里配置的模型只供总管使用。Codex、Claude Code、OpenCode 继续读取本机原生配置与认证，平台不会把总管的 API Key 发给它们。

## 配置模型

首次运行 `chiliarch init` 时可以配置，也可以登录后打开“配置”。至少核对这四项：

| 设置 | 填写内容 |
| --- | --- |
| 模型 API | 与服务商提供的请求格式一致 |
| 模型名称 | 服务商给出的实际 model ID |
| API 地址 | 对应格式的 API 根地址；不要填写某次请求的最终 endpoint |
| API Key | 服务商的认证密钥；无认证的自建网关可留空 |

例如，OpenAI 兼容服务常给出以 `/v1` 结尾的根地址；不要自行追加 `/chat/completions` 或 `/responses`。具体以服务商说明为准。不要把 Key 发到聊天里，使用配置页或 `CHILIARCH_MODEL__API_KEY` 环境变量。

模型必须支持工具调用，总管才能执行管理操作。未配置模型时，平台仍能手动管理；总管请求和协调事件会保留，配置后继续处理。

### 三种 API

| 请求格式 | `model.api_mode` | 最大输出 tokens |
| --- | --- | --- |
| OpenAI Chat Completions | `chat_completions` | 默认不传，使用服务端默认值 |
| OpenAI Responses | `responses` | 默认不传，使用服务端默认值 |
| Anthropic Messages | `anthropic` | 必填，由你填写模型支持的正整数 |

Anthropic 的输出上限保存为 `model.anthropic_max_tokens`，平台不猜测固定值。OpenAI 两种格式需要手动限制时，在“额外请求参数”或 TOML 的 `model.request_params` 中填写服务商支持的字段：Chat 常用 `max_completion_tokens`，部分兼容服务使用 `max_tokens`；Responses 使用 `max_output_tokens`。**手动填写的值会发送**。

Anthropic 也接受 `request_params.max_tokens`，同时填写时专用字段优先。切换请求格式后，检查额外参数是否仍适用。

### 思考与兼容开关

只启用当前服务支持的参数。公开思考能否显示，取决于服务商是否返回可读内容或摘要；平台不会编造思考，也不展示加密内容或签名数据。

| 设置 | 作用 |
| --- | --- |
| 请求推理 / `reasoning_enabled` | Chat 格式下可自动请求 `enable_thinking=true` |
| 发送 enable_thinking 参数 / `enable_thinking_param_enabled` | 默认开启；关闭后完全省略该字段，包括额外参数中的同名值 |
| 推理强度 / `reasoning_effort` | 按 API 支持的方式传递推理强度 |
| Thinking / `thinking_enabled`、`thinking_budget_tokens` | 使用服务支持的 thinking 设置 |
| 推理回放 / `reasoning_replay` | 后续请求保留服务支持的原生推理记录 |
| 流式用量 / `include_usage` | 请求用量；网关不支持时可关闭 |

若返回 `400 Unsupported parameter(s): enable_thinking`，关闭“发送 enable_thinking 参数”，保存后重新发送。关闭是**不传字段**，不是发送 false；不影响推理强度、Anthropic thinking 或已有公开思考的展示。

其他可选项包括 Temperature、自定义请求头、额外请求参数、请求超时、重试次数、tool choice，以及将 Chat 系统提示改以 user 角色发送的兼容开关。没有特殊需求时保持默认。额外参数不能覆盖平台生成的消息、工具、模型或流式控制字段。

## 审批模式

默认 `auto`，可在对话页或配置页选择：

| 模式 | 查询 | 改变状态的操作 |
| --- | --- | --- |
| `ask` | 直接执行 | 每项询问你 |
| `auto` | 直接执行 | 总管按风险判断；固定高风险操作仍需你批准 |
| `yolo` | 直接执行 | 总管自主执行 |

下级 agent 请求同样遵循该模式。总管可以在模式允许时处理其他 agent 的申请，但不能批准自己的待审批操作；这类许可由登录用户决定。管理页面中你直接提交的操作视为该次授权。

需要许可时，在对应工具下方点击批准或拒绝。批准绑定当时的操作与参数；更改模式不会自动批准旧申请。

这是平台业务审批。原生 Codex、Claude Code、OpenCode 的工具权限继续生效。当前没有替原生宿主回答交互审批或用户输入的通用桥，遇到必须交互的工作应在原生宿主处理，或按自己的原生设置调整运行方式。

## 上下文窗口与自动压缩

把 `model.context_window` 设置为模型实际支持的容量，默认 **200000 tokens**。使用量达到 **90%** 时，总管用当前模型生成接续摘要，再继续工作。

摘要保留目标、限制、用户修正、任务和请求 ID、已完成结果、待办及未知状态，近期完整工具调用与结果一起保留。完整聊天记录仍在平台里，压缩只缩短后续请求的活跃上下文。

页面显示占用与“正在压缩上下文”。有服务商用量时优先使用；没有时显示标有“约”的本地估算。缓存输入也占上下文容量，不能把累计账单用量当成当前窗口。

压缩会额外调用模型，带来等待与费用，也可能损失细节；重要结论可回看完整记录。压缩失败时保留原上下文并停止当前运行，不重复执行已经产生副作用的工具。

如果当前问题或必须保留的资料本身过大，需要缩短输入或核对容量。输出 tokens 与上下文窗口是不同设置。平台不另设最大工具轮次、消息条数或全局并行运行上限；同一会话只允许一个活跃运行，超时、审批和服务商限流仍然有效。

## 对话页面与键盘

进入对话页默认恢复当前浏览器上次打开的会话；没有记录或会话已删除时，显示新对话。指定会话的链接优先。恢复历史不会再次调用模型。

右侧会话列表默认收起，鼠标移到右边缘时显示，也可以点按钮固定展开。触屏和键盘使用按钮打开；Escape 或关闭按钮收起。每个会话可重命名或删除，首次成功问答后由模型自动命名；命名失败不影响回答，手工标题不被覆盖。自动命名会产生一次额外模型请求。

回答、公开思考与工具调用按发生顺序穿插显示，刷新后保留顺序。公开思考默认展开；长内容在限定高度内滚动，上翻阅读时暂停跟随新内容，回到底部后继续。可点击标题折叠，后续输出不会把手动折叠的部分重新打开。工具详情独立折叠，审批按钮留在对应工具下方。

| 按键 | 行为 |
| --- | --- |
| Enter | 发送 |
| Shift + Enter | 换行 |
| Ctrl / ⌘ + Enter | 发送 |

输入法确认候选词时不会发送。阅读历史时，新输出不会强行滚到底部；点“回到最新”或发送消息可以恢复跟随。代码块和回复支持复制，动画遵循系统“减少动态效果”设置。

切换会话时各自草稿保留在当前页面；刷新或离开页面不保存草稿。左侧导航、主题与上次会话选择保存在当前浏览器，清理站点数据会重置这些偏好。

## 流式、取消与错误

关闭浏览器不停止总管的后台运行。需要停止时点击停止按钮。停止会撤回尚未执行的许可，但不能撤销已经完成的外部操作，也不会自动取消 agent 已在执行的任务。

正在运行或等待审批的会话需要先停止再删除；仍关联未结束目标时，也需先处理该目标。模型中途失败会保留已经显示的内容和操作记录，下一次继续前先核对结果。

重启平台后，正在运行的总管轮次会标为中断，等待审批的工作按原许可记录恢复。模型或 API 地址已经改变时，需要核对再继续，不能把旧调用直接续到不兼容的配置。

## 下级来信

Agents 的提问与操作申请会持久保存。任务完成、失败、停滞或失联也会提醒总管核查。相关事件回到原目标会话；会话正在运行或等许可时，后来事件排队，不打断当前轮次。普通心跳和进度不会逐条调用模型。

总管对消息路由、讨论查询等无需模型判断的操作，不逐条生成回答。失联只触发核查，不会被当成任务已经停止。

默认会对临时连接故障、限流及服务端错误退避开启最多 3 次核查轮次。核查读取已知结果和实际任务状态，不重放失败前的工具。用户停止、认证错误、无效参数或用尽恢复次数后，自动协调暂停；未处理事件仍保留。

你可以发新消息，或在“目标”点击“继续协调”恢复。停止总管与取消 agent 任务是两件事，分别处理。

## 模型报错时怎么处理

| 错误或现象 | 处理 |
| --- | --- |
| 未配置模型 | 填写模型 ID、格式和 API 地址；Key 按服务商要求设置 |
| 401 / 403 | 检查 Key、服务商权限、地址以及自定义认证头 |
| 400、参数不支持 | 核对 API 格式与额外参数；enable_thinking 错误关闭对应开关 |
| Anthropic 缺少 max_tokens | 填写 Anthropic 最大输出 tokens |
| 429、临时 5xx 或 overloaded | 等待退避恢复，核对服务商限流和可用性 |
| 输出一半后失败、没有完整终态 | 已完成操作仍保留；先看工具结果，再决定继续或重试 |
| 上下文过长 | 核对实际窗口，缩短单条输入；查看压缩是否失败 |
| 总管停止后不再处理来信 | 发新消息或点击“继续协调” |
| 没有公开思考 | 服务可能未返回，核对它支持的推理参数；不会补造思考 |

配置页可读取近期脱敏日志。记录错误类型、时间、模型和请求格式便于排查，避免粘贴 Key 或带认证的完整请求。[更多配置](configuration.md) · [目标与验收](coordination.md)。
