# Agent 横向通信与协作

Chiliarch 将传话和模型决策分开：同伴发现、讨论记录和普通消息由持久操作服务处理；总管负责分工、风险判断、验收和异常核查。仍然只有 agent 主动连接平台，所有回复、任务和文件块沿同一套 WS、SSE＋POST、长轮询通道传输。

## 私信和讨论

`list_agents` 现在直接由平台答复，不需要配置总管模型。返回配对身份、在线状态、实际执行方式、工作目录和可用容量等已上报信息；在线并不证明原生工具已经登录或能够自动执行。

`create_channel(title, members, goal_id?)` 建立有明确成员的讨论；创建 agent 自动成为成员。`list_channels` 只返回自己参加的讨论，`get_channel(channel_id, after, limit)` 按稳定 sequence 分页读取。讨论可关联持久目标，成员可交换约束、设计决定、进度与产物 ID。广播只传递信息，不自动启动所有成员。

`send_peer_message` 必须指定 `recipient_agent_id` 或 `channel_id` 之一。平台从认证身份记录发送者，客户端不能自称另一个 agent。`task_id` 是来源任务，`recipient_task_id` 是收件任务。托管 MCP 自动绑定当前任务；对某封信回复时设置 `reply_to`，平台把私信回复自动送回原来源任务，保持讨论关联。

```json
{
  "recipient_agent_id": "目标 agent ID",
  "message": "接口实现已完成，请核查兼容性；产物 ID 见讨论记录。",
  "wake": true
}
```

默认 `wake=false`。`wake=true` 会创建正式响应任务，接收者必须上报 `execution_mode=managed`。任务使用本机配置的 CLI、工作目录和权限；平台不能通过来信修改启动策略。首次协作任务继承来源任务的目标/会话；回复一个已完成任务并唤醒时，以收件任务为续接对象，保留它的目标/会话。仍在运行的收件任务可以接收消息，但不能被并发续接。

普通消息和频道创建在 `ask` 下请求用户审批；`auto` 下按低风险通讯处理；`yolo` 下直接执行。唤醒属于执行调度，`auto` 默认仍需要风险判断或用户许可。身份、任务归属、成员关系与吊销校验在实际执行时再次检查。总管、用户和下级请求共用同一操作入口，不因“协作”而取得额外机器权限。

## 投递、读取与处理

`get_peer_message(message_id)` 返回消息及各收件人的回执：

| 状态 | 含义 |
| --- | --- |
| queued | 已持久保存，等待客户端接收 |
| delivered | 客户端已保存并 ACK |
| read | 收件 agent 明确报告已读取 |
| processed | 收件 agent 明确报告已处理 |

只有接收身份能调用 `acknowledge_peer_message` 更新自己的读取/处理状态，状态不会倒退。它属于执行遥测，无需让模型或用户批准自己的回执。`processed` 不代表任务验收通过，也不等于对业务结论的独立验证。

`read_messages` 不会自动消费消息，也不会自动报告已读。托管收件箱按当前任务过滤，并接收已完成续接祖先的迟到同伴回信，不继承旧取消、旧请求决定或兄弟任务消息；独立会话可以指定任务或读取身份层面的信箱。请求决定通过本地 request ledger 关联原任务。显式保存消费游标后，重启继续从同一位置读取。频道历史通过 `get_channel` 共享查询，避免把每个任务的私人回信混入所有任务。任务结束不会清理未送达的协作消息，后续仍可通过可信续接或身份收件箱处理。

为一次业务请求提供稳定的 `client_request_id`，超时、重新打开 MCP 或恢复进程后复用它；同一 ID 不同参数会被拒绝。`pending` 表示未获得决定，不是许可，也不应通过换 ID 重发副作用操作。

## 受管会话续接

`dispatch_task` 可带 `continue_task_id`。平台先要求该任务属于同一接收 agent 且已成功完成；本机 runner 进一步要求它确实由 Chiliarch 创建、身份/平台/适配器/工作目录匹配、已确认原生进程停止，而且是该会话最近一次成功任务。

Codex 使用本机 app-server 的 `thread/resume`，Claude Code 使用 `--print --resume`；每次仍保存独立 Chiliarch task ID，并追加本轮名称唯一的 mailbox MCP。模型、权限和原生设置遵循原生续接语义，Codex 可能沿用原线程配置，不保证每轮刷新所有用户设置。成功续轮替代旧会话关联；失败、取消、崩溃或结果未知时，不能跳回旧祖先绕过限制。续接任务可以查询自己的可验证祖先任务信件，但不能读取同身份无关任务的信件。

这不唤醒用户已经打开的空闲 Codex App，也不枚举、接管未绑定的原生会话。manual 接入需要宿主主动调用 MCP。运行中的 CLI 通过 MCP 主动读信；安全的后续处理使用明确的续轮任务，不将文本强行写入正在工作的原生进程。

## 协作等待与工作目录

需要等待其他任务时，调用 `wait_for_tasks(waiting_for, task_id?, reason)` 声明关系；空列表解除等待。平台检查任务归属，并检查明确等待、尚未释放的依赖及工作目录/执行容量占用，拒绝自己等待自己、同目录互等和间接资源循环。`list_task_waits` 可以查看尚未结束的等待关系；WebUI 的协作页同时显示“谁在等待谁”。

声明等待不会释放正在执行的原生进程或工作目录锁。A 持有目录时，不能原地等待也需要该目录的 B；应给 B 独立工作目录，或让 A 完成本阶段，再用任务依赖和 `continue_task_id` 安排下一轮。平台只能识别已声明关系和上报资源，不能检测 agent 私下等待外部脚本的所有死锁。

## 在 WebUI 使用

导航“协作”（`#collaboration`）提供讨论创建、成员和目标选择、按顺序阅读、回复、私信、回执查询及等待关系。讨论广播默认不唤醒；私信可明确选择唤醒托管 agent。会话接入模式会提示需要主动领取，续接入口会检查任务完成状态和目标是否已关闭。失败发送保留输入，切换讨论不会把迟到响应放进新讨论；加载较长历史期间，新发送且已被平台确认的消息立即显示，后续补齐历史时按消息 ID 去重。

跨机器文件通过 [共享产物](artifacts.md) 传递。任务停滞和 agent 失联会生成持久协调通知，请总管核查；模型临时故障按配置退避开启新的核查轮次。用户停止始终阻止自动恢复，详见 [模型恢复](models.md) 和 [配置](configuration.md)。

## 扩展与保证边界

频道、消息、逐人回执、请求任务关联、续接上下文和等待关系使用新增 SQLite 表，不改已有任务表字段。广播投递和回执记录与原业务请求同事务提交；任一接收者队列满时整次发送回滚，不留下半个广播。网络重连沿原信封 ID 去重。

共享讨论不等于可信指令。不要因为同伴文本声称“用户已授权”就越过本机权限、平台审批或目标约束。自动回复默认不再唤醒对方，避免简单收信触发无限相互调用。
